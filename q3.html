From Type to Code

A look at how typesetters, designers and developers arrange words on a page

Old-fashioned typesetting

Before computers, every printed page was built by hand. A typesetter, also called a compositor, picked individual metal letters out of a type case and lined them up in a composing stick, one character at a time. Capital letters were stored in the upper case and small letters in the lower case, which is where those terms come from. Thin strips of lead were placed between lines to space them out, giving us the word "leading." Once a page was locked in and printed, changing even one word meant pulling the type apart and setting it again.

Desktop publishing

In the mid-1980s, personal computers like the Apple Macintosh, layout programs like Aldus PageMaker, and affordable laser printers moved typesetting onto a desk. Designers could choose fonts, adjust spacing, and place images on screen, then print exactly what they saw. Work that once required a print shop could be done by one person in a fraction of the time. The end product was still a printed sheet, though, with every element sitting in a set spot on paper of a set size.

HTML

HTML, created by Tim Berners-Lee in the early 1990s, changed the goal. Instead of locking words into one layout, HTML describes what each piece of content is: a heading, a paragraph, a list, a link. The browser decides how to display it, so the same file can appear on a large monitor, shrink to fit a phone, or be read aloud by a screen reader. The writer gives up exact control over layout in exchange for content that can travel almost anywhere.

CSS

CSS, introduced in the mid-1990s, handles the visual side that HTML leaves out. Fonts, colours, spacing, and layout are written as rules in a stylesheet and applied across a page or an entire website. In a way, CSS brings back the typesetter's craft of choosing type and spacing, but the rules are applied automatically and can be updated in one place instead of letter by letter.

Comparing the four

All four methods share the same purpose: arranging text so it is clear and readable. Typesetting and desktop publishing both aim for a finished, unchanging page, but one is physical and slow to correct while the other is digital and quick to edit. HTML and CSS split that job in two, with HTML handling structure and meaning and CSS handling appearance. The result is less control over exactly how a page looks, but far more flexibility in where and how it can be read.
