From Type to Code

A quick look at how typesetters, designers and developers get words onto a page

Old-fashioned typesetting

Before computers, every page had to be put together by hand. A typesetter (also called a compositor) would pick individual metal letters out of a type case and line them up one at a time in a tool called a composing stick. Fun fact: capital letters were kept in the upper case and small letters in the lower case, which is literally where we get "uppercase" and "lowercase" from. They also put thin strips of lead between lines to space them out, and that's where the word "leading" comes from. The catch was that once a page was printed, fixing even one typo meant taking the type apart and setting it all over again.

Desktop publishing

Then in the mid-1980s, things changed fast. The Apple Macintosh, layout software like Aldus PageMaker, and laser printers that people could actually afford brought typesetting right to someone's desk. Designers could pick fonts, play with spacing and move images around on screen, then print exactly what they saw. From a business point of view, that's a massive efficiency gain, since one person could now handle work that used to need a whole print shop. The end goal was still a printed page, though, with everything locked into a set spot on paper of a set size.

HTML

HTML came along in the early 1990s thanks to Tim Berners-Lee, and it flipped the whole approach. Instead of placing words in an exact spot, HTML just labels what everything is, like a heading, a paragraph, a list or a link. The browser figures out how to display it, so the same file can work on a big monitor, a phone, or even be read out loud by a screen reader. You lose some control over the exact layout, but your content can go pretty much anywhere.

CSS

CSS showed up in the mid-1990s to handle the visual side that HTML leaves out. Fonts, colours, spacing and layout all get written as rules in a stylesheet that can apply to one page or a whole website. The way I see it, CSS kind of brings back the typesetter's job of choosing type and spacing, except now the rules apply automatically and you can update everything from one place instead of letter by letter.

Comparing the four

At the end of the day, all four are trying to do the same thing, which is make text clear and easy to read. Typesetting and desktop publishing both aim for a finished page that doesn't change, but one is physical and slow to fix while the other is digital and way faster to edit. HTML and CSS split the work in two, with HTML covering structure and meaning and CSS covering the look. You give up some control over exactly how things appear, but you gain a lot of flexibility in where and how people can read your work.
