Google Docs vs. HTML: What's Actually Different?

I've used Google Docs for basically every assignment I've ever written, so starting HTML this term was a bit of an adjustment. Both let you put words on a page, but they work in pretty different ways. Here are the main differences I've noticed so far.

What you see vs. what you type

Docs is what's called WYSIWYG, which stands for "what you see is what you get." You hit bold, it turns bold, done. With HTML you're typing plain text and wrapping it in tags like <p> and <h2>, and you don't really see the final product until you open the file in a browser. It's kind of like the difference between building a slide in PowerPoint yourself and writing out instructions for someone else to build it.

Looking organized vs. being organized

In Docs you can make a line big and bold so it looks like a heading, even if you never touched the heading styles. HTML pushes you to say what each thing actually is. A heading goes in a heading tag, a paragraph goes in a paragraph tag, and so on. That structure is what lets screen readers and search engines understand how the page is put together.

Where the styling goes

In Docs, your font, colour and size choices get attached right to whatever text you highlighted. With HTML, the content and the styling are kept separate. HTML holds the words and structure, and CSS takes care of the look. The upside is efficiency, since changing one rule in your stylesheet updates every heading at once instead of fixing them one by one.

Pages vs. screens

Docs is built around a printed page, with margins, page sizes and page breaks. HTML doesn't really have pages. The text just reflows to fit whatever screen it's on, whether that's a laptop or a phone, which makes a lot of sense now that so many people read everything on their phones anyway.

Saving and sharing

Docs saves to the cloud automatically and you share it with a link. Group projects are easy because everyone can edit at the same time and leave comments. An HTML file is just a file on your computer that ends in .html. You can open it in your own browser, but if you want other people to see it online, you have to upload it to a web server first.

So which one wins?

It really depends on what you're doing. For drafts, group assignments and anything you're printing or keeping private, Docs is the easier choice. If the content is going on the web and needs to work on any device, HTML is the way to go.
